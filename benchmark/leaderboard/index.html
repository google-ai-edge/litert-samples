How the rows are measured

One session, one model file, one accelerator. A row is one job of a litert benchmark --ddp session. The Developer Device Platform runs LiteRT's prebuilt benchmark_model for Android arm64, at the release named in the Runtime column, against the model file it pushes to each device in the matrix, and pulls the results back.

What benchmark_model does on the device. The CLI passes --graph, --use_gpu=true for GPU rows and the two result-file flags, nothing else, so the binary runs at its own defaults, which the CLI mirrors: a warm-up of at least 0.5 s, then 50 runs or at least 1 s, whichever takes longer, up to 150 s, on its default thread count. Runs is the count the device completed. Each row reports p95 and the run count from a single session.

Where each number comes from. Median, Avg, p95, Init and First inference are the latency metrics in results.pb; Footprint is its overall memory footprint. Nodes delegated is read from the device log line Replacing N out of M node(s) with delegate (X), so the delegate name and N/M are the device's own report. Init on the GPU includes the delegate initializing the graph.

Reading the board. Rows are ordered by median latency and compared only within one device, accelerator and task; the filters above make that comparison. Rows are produced by a maintainer running the driver and committed here as data: board.json is this board, measurements.jsonl every job, and the README beside this page says how a row is made and how to add a model.
